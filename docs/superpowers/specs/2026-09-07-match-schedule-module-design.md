# LifeHub 比赛日程模块设计

## 1. 背景与目标

用户会从雷速体育及其他体育平台查看未来赛程，但可能因未及时关注而错过比赛。LifeHub 需要增加一个不绑定足球或单一平台的“比赛日程”模块，让用户提前导入未来比赛，并在比赛开始前收到固定提醒；比赛结束后继续保留为可检索、可折叠的赛事档案。

第一阶段保持 Android、离线优先：识别、存储和提醒均在本机完成，不依赖服务器、域名或雷速体育内部接口。

### 目标

- 支持足球、篮球、网球、电竞等双参赛方比赛。
- 支持未来赛程截图、CSV、ICS 和手动添加。
- 支持一次选择多张截图并导入多场未来比赛。
- 所有未来比赛固定安排开赛前 8 小时和 1 小时两次本地提醒。
- 支持比赛改期、延期、取消和待补结果状态。
- 支持为已有比赛手动补录比分。
- 支持直接录入一场已经结束的比赛。
- 已结束或取消的比赛保留在按年份、运动和赛事折叠的档案中。

### 第一阶段不做

- 不抓取雷速体育或其他平台的内部接口。
- 不登录、保存或代理任何体育平台账号。
- 不识别正在进行、已经结束、赔率、预测或比分直播截图。
- 不自动联网更新开赛时间或最终比分。
- 不上传截图，也不提供云端 OCR。
- 不提供提醒时间、提醒开关或提醒设置入口。
- 不支持多人协作或跨设备同步。

## 2. 已确认的产品方案

采用本地 OCR 与通用规则解析。解析逻辑依据日期、时间、赛事名称和双方参赛者等文字结构，不依赖雷速体育的固定坐标。可以为常见平台提供辅助特征，但平台特征不能成为识别成功的必要条件。

比赛主页采用三状态分页：

1. **即将开始**：浏览、搜索、筛选未来比赛。
2. **待补结果**：处理已经到达开赛时间但尚未录入最终结果的比赛。
3. **赛事档案**：查看已结束、取消和已完成补录的历史比赛。

新增功能统一放在右上角加号入口中：

- 从截图识别；
- 手动添加未来比赛；
- 录入已结束比赛；
- 导入 CSV 或 ICS。

主页不承载识别预览、比分编辑或档案展开的复杂操作。点击比赛卡片进入详情页，可执行编辑、延期、取消和删除。

## 3. 模块入口与页面

在数据页模块列表中增加：

- 模块 ID：`matches`
- 标题：`比赛日程`
- 描述：`导入未来比赛、固定提醒并保留赛事档案`
- 图标：体育或奖杯类 Material 图标

模块遵循数据页现有的固定、排序和隐藏规则。隐藏入口不删除比赛记录。

页面组成：

### 3.1 比赛主页

- 顶部：返回、标题、搜索、添加。
- 分页：即将开始、待补结果、赛事档案。
- 筛选：全部、运动类型、赛事、日期范围。
- 即将开始按日期分组，卡片展示运动、赛事、阶段、参赛方、日期、时间、场地和直播平台中的有效字段。
- 页面和卡片均不显示固定提醒时间、提醒状态、提醒开关或提醒设置。

### 3.2 统一新增入口

点击加号弹出底部选择面板。选择导入方式后进入独立流程，避免主页堆叠表单和按钮。

### 3.3 识别预览页

- 展示从截图、CSV 或 ICS 解析出的比赛草稿。
- 每场比赛可勾选、编辑或移除。
- 正常字段使用默认样式；低可信或缺失字段标红。
- 疑似重复项标注为“可能已存在”，由用户选择跳过或更新。
- 所有已勾选记录都完成修正后才允许保存；不准备导入的异常记录可以取消勾选。

### 3.4 待补结果页

- 展示已经到达开赛时间但没有最终结果的比赛。
- 支持快速填写主比分，也可进入详情填写加时、点球、局分等补充信息。
- 保存最终比分后，比赛状态变为已结束并进入赛事档案。

### 3.5 赛事档案页

默认折叠层级为：年份 → 运动与赛事 → 比赛。

档案支持按球队、选手或赛事搜索，并支持运动类型、赛事、状态和年份筛选。年份根据比赛日期生成；跨年赛季单独显示用户保存的赛季字段，例如 `2026/27`。

## 4. 数据模型

第一阶段只新增一张比赛记录表，避免为一次使用拆分球队、赛事和赛季关联表。现有通用提醒表继续用于保存比赛提醒。

### 4.1 比赛记录

字段包括：

- `id`：本地唯一 ID。
- `sportType`：运动类型，必填，允许用户自定义。
- `competition`：赛事名称，必填。
- `season`：赛季，可选。
- `stageOrRound`：阶段或轮次，可选。
- `participantA`、`participantB`：双方球队或选手，必填。
- `matchDate`：比赛当地日期，必填。
- `startAt`：带时区换算后的开赛时刻；未来比赛必填，历史比赛允许为空。
- `timezoneId`：来源时区；未来比赛必填。
- `scoreA`、`scoreB`：主比分，可选。
- `scoreDetail`：加时、点球、局分或其他比分说明，可选。
- `status`：`SCHEDULED`、`POSTPONED`、`CANCELLED`、`PENDING_RESULT`、`FINISHED`。
- `venue`：场地，可选。
- `broadcast`：直播平台，可选。
- `notes`：备注，可选。
- `favorite`：收藏状态。
- `sourceType`：`SCREENSHOT`、`CSV`、`ICS`、`MANUAL`。
- `sourceKey`：用于重复检查的来源键，可选。
- `sourceLabel`：来源说明，可选，例如“雷速体育截图”。
- `createdAt`、`updatedAt`：创建和更新时间。

不保存原始截图。来源字段和稳定标识为以后接入合法的自动数据源保留迁移空间，但第一阶段不实现联网数据源接口。

### 4.2 提醒关联

现有提醒表使用比赛 ID 作为实体 ID，实体类型为 `MATCH`，提醒种类分别表示开赛前 8 小时和 1 小时。界面不暴露这两个值。

## 5. 状态流转

```text
识别或手动添加
  → 导入预览
  → SCHEDULED
      → POSTPONED → 确认新时间后回到 SCHEDULED
      → CANCELLED
      → 到达开赛时间后转为 PENDING_RESULT
          → 填写最终结果后转为 FINISHED
```

规则：

- 取消比赛关闭提醒但保留档案。
- 延期比赛关闭现有提醒；确定新时间后重新安排。
- 到达开赛时间不自动认定比赛结束，也不猜测比分。
- 手动录入已结束比赛直接保存为 `FINISHED`，不创建提醒。
- 已结束或取消比赛只在用户主动删除时移除。

## 6. 截图识别与导入流程

### 6.1 本地识别

1. 用户一次选择一张或多张未来赛程截图。
2. 图片在本机按顺序处理；大图先缩放，避免同时占用过多内存。
3. 本地 OCR 提取中文、英文、数字和常用符号。
4. 通用解析器识别日期标题、比赛时间、运动、赛事和双方参赛者。
5. 日期标题自动作用于其下方的比赛行。
6. 赔率、预测、新闻、直播比分和完场内容不生成草稿。
7. 原截图在识别结束后不复制到应用附件目录。

### 6.2 草稿校验

未来比赛至少需要运动类型、赛事、双方参赛者、日期、开始时间和时区。无法推断的运动类型可以让用户为当前批次统一选择，再允许逐条修改。

草稿分为：

- 正常：字段完整且可信。
- 待确认：存在低可信字段。
- 无法导入：缺少核心字段。
- 疑似重复：与本地记录可能相同。

### 6.3 重复检查

优先使用来源稳定标识；没有稳定标识时，使用标准化后的运动、赛事、双方参赛者、日期和时间比较。

解析器不自动覆盖本地数据：

- 完全相同的记录默认跳过。
- 参赛方和赛事相同但时间不同的记录标记为可能改期。
- 用户明确选择更新后，才修改原比赛并重新安排提醒。

### 6.4 保存

用户确认后，所选草稿在同一数据库事务中写入。任何数据库写入失败都回滚整批导入，避免只保存部分记录。事务成功后再同步本地通知；通知同步失败时保留比赛数据并在下次应用启动时重建未来比赛通知。

## 7. CSV 与 ICS

### 7.1 CSV

应用提供 UTF-8 模板，标准列为：

```csv
运动类型,赛事,赛季,阶段或轮次,参赛方A,参赛方B,比赛日期,开始时间,时区,场地,直播平台,备注
足球,英超,2026/27,第4轮,阿森纳,切尔西,2026-09-07,20:00,Asia/Shanghai,某体育场,某平台,
```

额外列忽略，缺少必填列的记录进入待确认状态。CSV 不直接写库，必须经过统一预览和重复检查。

### 7.2 ICS

复用现有 ICS 读取基础能力，从事件标题、描述、地点、开始时间和时区生成比赛草稿。标题无法可靠拆出双方参赛者时，要求用户在预览页修正。ICS 同样不绕过预览。

## 8. 固定提醒

提醒规则不可设置、不可关闭，任何应用页面都不显示“8 小时”“1 小时”或提醒配置。

- 距离开赛超过 8 小时：安排两次提醒。
- 距离开赛不足 8 小时但超过 1 小时：只安排尚未过期的 1 小时提醒。
- 距离开赛不足 1 小时：不补发已经错过的提醒。
- 修改开赛时间：取消旧通知并按新时间重建。
- 延期或取消：取消旧通知。
- 手机重启、时区变化、应用更新或应用重新启动：校验并重建未来比赛通知。

通知内容只展示运动、赛事、双方参赛者和开赛时间，不解释提醒提前量。

Android 厂商的电池优化和系统调度可能造成少量延迟，应用使用系统允许的最高本地通知精度，但不承诺所有设备严格精确到分钟。

## 9. 手动录入与比分

### 9.1 手动添加未来比赛

运动、赛事、双方参赛者、比赛日期、开始时间和时区必填；其他字段可选。保存后按固定规则创建提醒。

### 9.2 手动录入已结束比赛

运动、赛事、双方参赛者、比赛日期和最终状态必填；开始时间可选。可以只填写双方主比分，也可增加比分详情。保存后直接进入赛事档案，不创建提醒。

### 9.3 补录已有比赛结果

待补结果页允许填写 `scoreA`、`scoreB` 和 `scoreDetail`。比分字段必须成对填写；仅有文字结果时可使用比分详情，并将状态明确设为已结束。

## 10. 异常处理与性能

- OCR 失败不写入数据库，并允许用户重新选择图片或改为手动添加。
- 未确认的低可信字段会阻止该条记录被选中保存；用户可以修正该记录或取消勾选。
- 批量保存只提交用户已勾选且校验通过的记录；这些记录整体成功或整体回滚。
- 多张大图逐张缩放和识别，识别结果合并后进入预览。
- 文件导入继续遵守应用现有的文件大小和记录数量上限。
- 重复导入不会产生重复比赛和重复通知。
- 新表必须纳入备份、恢复和数据健康检查；旧备份中没有比赛数据时正常恢复其他内容。第一阶段只提供比赛模块内搜索。

## 11. 测试要求

### 11.1 领域与数据库测试

- 数据库迁移不破坏现有数据。
- 状态流转、比分校验和历史比赛日期规则。
- 批量导入事务回滚。
- 重复检查和明确更新行为。
- 备份、恢复和数据健康检查。

### 11.2 识别与导入测试

- 雷速体育以及至少两种不同布局的未来赛程截图夹具。
- 足球、篮球、网球和电竞对阵格式。
- 单图多场、多图多场、跨日和跨月。
- 中文队名、英文队名、数字队名和青年队标记。
- 低可信字段、缺失日期、缺失时间和疑似重复。
- 确认赔率、直播比分和完场行不会生成未来比赛草稿。

### 11.3 提醒测试

- 超过 8 小时、1 至 8 小时和不足 1 小时三种导入时间窗口。
- 改期、延期、取消和删除时通知同步正确。
- 重启或时区变化后不会重复安排同一通知。
- 所有界面均不存在提醒提前量或设置入口。

### 11.4 页面测试

- 三个分页、搜索、筛选和空状态。
- 统一新增入口及四种新增方式。
- 导入预览、低可信标红和重复选择。
- 快速补比分、详细赛果和手动录入已结束比赛。
- 年份、运动和赛事三级折叠档案。

## 12. 完成标准

- 用户能从多个体育平台的未来赛程截图中批量生成可编辑草稿。
- 未经用户确认，识别结果不会写入数据库或创建通知。
- 未来比赛按固定规则创建本地提醒，且界面不显示或允许设置提醒时间。
- 比赛改期、延期、取消和到达开赛时间后的状态正确。
- 用户能手动补比分或直接录入已结束比赛。
- 历史比赛可按年份、运动和赛事折叠、搜索和筛选。
- 新数据可备份、恢复并接受数据健康检查，比赛记录可在模块内搜索。
- 静态分析、现有测试和新增比赛模块测试全部通过。
